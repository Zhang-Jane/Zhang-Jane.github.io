学 SEO 时最烦的一件事，是名词一堆、说法还互相矛盾。我把我笔记里零散的概念重新理了一遍：按**类别**放，每条尽量用大白话说明白「是什么」「为啥要在意」「2026 年现在一般怎么看」「平时可以怎么用」。它和站里那篇 [《SEO入门指南（2026版）》](https://zhang-jane.github.io/post/42ec87f3.html) 是互补的——那边偏建站与整体流程，这篇当**词典 + 工具清单 + 排错备忘**。

下面有一条得先说清楚：**关键词密度**早年被吹得很神，现在早不是重点了。Google 更在意内容是否真解决问题、是否可信；塞词反而容易显得假。另一条是**域名权重、DA、PA、TF**这类数：多半是第三方工具算的**预测分**，方便你和竞品比个大概，**不是** Google 对外公布的「官方排名公式」。别为了涨分去搞歪门邪道，盯 Search Console 里的展示、点击和实际转化更靠谱。

## 一、常用名词（按类）

### 基础概念

**SEO（Search Engine Optimization，搜索引擎优化）**  
让网站在百度、Google 等自然结果里更容易被找到、排名更好，从而带来不花钱的搜索流量。核心是**对用户有用、对机器可读**，不是钻空子。2026 年主流声音很一致：原创、有依据、体验好，再加上下面说的 E-E-A-T。

**SERP（Search Engine Results Page）**  
用户搜完词之后看到的那一屏就是 SERP。现在上面不只有十条蓝链，还有精选摘要、相关问题、视频块，以及越来越多的 **AI Overviews（AI 概览）**。很多人扫一眼结果就得到答案，**不点进任何网站**——这就是所谓的零点击搜索。做内容的人得接受：曝光不一定等于点击，有时目标是「被引用」或品牌被看见。

**E-E-A-T（经验、专业、权威、信任）**  
Google 用来衡量内容是否靠谱的一套框架，近几年核心更新里经常拿它说事。

- **Experience（经验）**：你是不是真的用过、做过？有没有一手观察？
- **Expertise（专业）**：事实、术语、步骤是否经得起推敲？
- **Authoritativeness（权威）**：行业里有没有人引用你、链接你？
- **Trustworthiness（信任）**：网站是否透明——作者是谁、联系方式、隐私与条款是否清楚？

E-E-A-T 低的内容，一遇大更新就容易掉。页面上加**作者简介**、**可核对的出处**、**真实案例**，比堆关键词实在得多。

**白帽 SEO 与黑帽 SEO**  
白帽：按规则来，对用户诚实，效果慢但稳。黑帽：隐藏文字、买垃圾链接之类，轻则降权，重则站点从索引里消失。2026 年只建议走白帽。

### 关键词相关

**目标关键词与长尾关键词**  
目标词：你主打的那几个，流量相对稳定，比如「SEO 入门」。长尾词：更具体、单次搜索量不大，但往往**意图明确**，比如「2026 新手 SEO 教程 博客」。新手不必死盯「密度百分比」；把词**自然写进标题、小标题和正文**，并匹配用户到底想**了解**还是**购买**，更重要。

**搜索意图（Search Intent）**  
用户打字时真正想干什么：查资料、找官网、比价下单……同一关键词，意图不同，合适的页面类型也不同。内容和意图对不上，排名很难好看。

### 链接与权威

**外链 / 反向链接（Backlinks）**  
别的站点指向你的链接。**质量比数量重要**：相关行业、有公信力的站点链过来，比一千条论坛签名有意义。别人因为内容好而自愿引用你的链接，通常最有价值。

**内链（Internal Links）**  
站内页面互相链。用户好找相关内容，爬虫也好顺着发现页面、理解哪些页更重要。

**孤岛页面（Orphan Pages）**  
几乎没有内链指过去的页面。爬虫可能很晚才发现，用户也基本进不去。办法很直接：从主题相关的文章里加几条**读起来顺**的内链。

**域名权重、页面权重（多为第三方指标）**  
常见说法包括 **DA（Moz）**、**PA（Moz）**、**TF / CF（Majestic）** 等，都是工具根据链接数据**估算**的分数，用来横向对比还行，**别当成 Google 官方打分**。不同工具之间也不宜硬换算。

### 技术与页面优化

**hreflang**  
多语言、多地区站点用来标注「这个页面是给哪类语言/地区用户看的」。要注意：**互相指向要对得上**（A 标 B，B 也要标 A），并且指向的 URL 要是**能正常打开的 200 页面**。指到重定向链或坏链上，信号容易乱，甚至被忽略。

**Canonical（规范 URL）**  
内容重复或极度相似时，用 `<link rel="canonical">` 告诉搜索引擎「算权重时以这个 URL 为主」。同样应指向稳定可访问的页面，多语言场景下还要和 hreflang 策略一致，别各说各话。

**301 与 302**  
301：永久搬家，旧地址的权重多半能带到新地址。302：临时跳转，别拿来长期顶替 301。改版、换域名时 301 是标配。

**重复内容（Duplicate Content）**  
多个 URL 上摆着相同或高度相似的内容时，搜索引擎会挑一个当主版本，未必是你心里那个。用 canonical、合理的 URL 规则，比「多铺几个地址碰运气」靠谱。

**Sitemap（网站地图）**  
一般是 XML，列重要 URL，帮爬虫发现页面。**提交不等于必收录**，只是提高被发现的机会。

**robots.txt**  
告诉爬虫哪些路径**不建议抓**。**注意**：它管的是抓取，不是「禁止收录」；若不想进索引，要用 **noindex** 等更直接的机制，并查官方文档别误伤整站。

**富结果 / SERP 特性（Rich Results）**  
带星级、FAQ 展开、图文摘要等增强展示。结构化数据（Schema）做得好，有机会出现这类样式；同时 SERP 上功能越多，传统自然结果的点击可能被稀释，要和零点击趋势一起看。

### 其他值得单独记的

**Core Web Vitals**  
Google 用 LCP、INP、CLS 等衡量加载、交互、视觉稳定，和用户体验强相关，2026 年仍然值得认真做。**PageSpeed Insights** 能直接看 field 与 lab 数据。

**零点击搜索**  
答案直接出现在结果页，用户不再点进网站。优化目标有时要从「抢点击」扩展到「**被 AI 或摘要引用**」「**品牌仍被记住**」。

## 二、实用检测工具（日常够用）

下面这些多数有免费档，适合新手轮着用，不必一次全开会员。

- **hreflang**：用 [hreflangs.com](https://www.hreflangs.com/) 这类专项工具检查标签是否成对、是否指到正常 URL。
- **富结果 / 结构化数据**：[Google 富媒体测试](https://search.google.com/test/rich-results) 是官方入口。
- **可读性**：[Hemingway Editor](https://hemingwayapp.com/) 会把又长又绕的句子标出来，中文写作者也能借鉴「拆句」思路。
- **英文语法与风格**：[Grammarly](https://app.grammarly.com/) 适合英文站或双语稿。
- **翻译**：DeepL 在多数场景下比机翻自然，多语言站点可辅助，重要页仍建议人工审。
- **文本相似与原创**：Quillbot、Grammarly各类「AI/原创度」检测工具见仁见智，**别迷信单一分数**；
- **Sitemap**：[XML Sitemaps 验证器](https://www.xml-sitemaps.com/validate-xml-sitemap.html) 可检查格式是否规范。
- **整站抓取级审计**：Ahrefs Site Audit 等偏付费；免费侧可先用 **Chrome DevTools + Lighthouse** 做单页性能与体验审计。
- **性能与 CWV**：[PageSpeed Insights](https://pagespeed.web.dev/) 看 Core Web Vitals 与改进建议。
- **移动友好**：可用 [Sitechecker 移动友好测试](https://sitechecker.pro/mobile-friendly-test/) 等工具做快速抽查。
- **浏览器插件**：Ubersuggest 扩展、AITDK SEO Extension、SEO META in 1 CLICK 等，适合快速扫一眼标题、描述、索引相关标签。

**我自己的用法**：先 **Google Search Console + PageSpeed + 富媒体测试** 打底；写文章时用 Hemingway/Grammarly 控可读性；有多语言再跑 hreflang 专项检查。别为了「跑分」而跑分，工具是帮你少踩坑的。

## 三、常见问题与怎么处理

这些都是我或身边站点踩过、且 2026 年仍然常见的坑。

1. **搜索结果标题和你在 `<title>` 里写的不一致**  
   Google 有时会改标题，常见原因是太长、堆词、或与页面实际内容差太远。**尽量**把标题控制在约 50–60 个字符（英文计数习惯，中文可略放宽）、读起来像人话，且和 H1、首段主题一致。

2. **孤岛页面**  
   没有合理内链，爬虫和用户都几乎进不去。从相关主题文章里加描述性锚文本，别堆「点击这里」。

3. **HTML `lang` 写错或缺失**  
   主要服务无障碍和浏览器语言行为；顺手写对没坏处，别指望单靠它拯救排名。

4. **某页只有一条 dofollow 内链指向**  
   显得像被遗忘的角落。重要内容应从多篇相关页自然链过来。

5. **正文从不指向外站**  
   适当引用权威来源（百科、论文、官方文档），读者和搜索引擎都更容易判断你在认真写。若不想传递权重，可用 `nofollow` 或 `sponsored`，按场景来。

6. **重复 URL 没有 canonical**  
   同一内容多个入口时，指定一个规范地址，避免权重分散。

7. **该收录的页没进 Sitemap**  
   Sitemap 不是万能，但重要 URL 应列进去并在 Search Console 里保持提交习惯。

8. **hreflang 指到 301/404**  
   和前面说的一样：必须指向**最终 200**、且双向一致，否则不如不加。

修完后在 Search Console 里**请求编入索引**或依赖自然抓取，别指望改完下一秒就变。

## 四、第三方指标表（竞品对比时用）

下表里的分数**多数是工具商的模型**，用来**横向对比**同一批竞品、判断难度，别当成「Google 官方排名因子表」。

| 指标                    | 常见出处    | 大致衡量什么              | 数据从哪来             | 范围/刻度       | 怎么用好                             | 容易误读的地方                     |
| ----------------------- | ----------- | ------------------------- | ---------------------- | --------------- | ------------------------------------ | ---------------------------------- |
| LPS                     | Mangools 等 | 某 URL 外链综合「硬度」   | 常整合 Moz/Majestic 等 | 0–100           | 看 SERP 前页对手，估竞争难度         | 不等于主题是否匹配                 |
| Keyword Difficulty (KD) | Mangools 等 | 关键词首页竞争强度        | 常基于 Top10 的 LPS 等 | 0–100，越高越难 | 配合长尾词，别只啃最高分词           | 偏链接维度，不等于内容难度         |
| SERP Features Impact    | Mangools 等 | SERP 特性对自然点击的稀释 | SERP 特性密度等        | 常见 1–5        | 判断是否值得做富媒体/视频            | 不是「难度分」，是点击被抢的风险感 |
| Domain Authority (DA)   | Moz         | 域名整体「潜力」预测      | Moz 链接库             | 0–100           | 看域名级趋势、和 PA 一起看           | 非 Google 信号；高分难涨也正常     |
| Page Authority (PA)     | Moz         | 单页潜力预测              | 页面级链接             | 1–100           | 对比你的目标页与对手页               | 不同工具分制不可硬换算             |
| Citation Flow (CF)      | Majestic    | 链接传播「量」的强度      | 外链图谱               | 0–100           | 和 TF 一起看量与质                   | 容易被刷量污染                     |
| Trust Flow (TF)         | Majestic    | 链接可信度、与种子站距离  | 图谱 + 种子集          | 0–100           | TF/CF 比高通常更干净；还要看主题相关 | 主题不相关时 TF 也会怪             |
| Referring Domains (RD)  | Majestic 等 | 链向你的**独立域名**数    | 去重域名               | 无上限          | 看外链广度，配合 TF                  | 注意统计口径是否含子域             |
| External Backlinks      | Majestic 等 | 外链条数总计              | 各索引库               | 无上限          | 结合 RD 看是否「少数域刷量」         | 同源多条会放大数字                 |

**一句实话**：这些表再漂亮，也不如 Search Console 里**哪些查询带来点击**来得实在。

## 五、系统化提升（和 2026 趋势对齐）

把事拆成四块，日常就不容易乱。

**1. 关键词**  
长尾词库持续补；看 Search Console 里**排名在 11–30 位**的词，往往改标题、补强首段和小标题，性价比最高。系列文章做成小专题，内链串起来。

**2. 内容**  
用 FAQ、案例、小标题把版面拆清楚；移动端读得顺、首屏别太慢。旧文定期更新事实与日期，加**亲身经历**比加关键词更安全。写清楚比写「像 SEO 范文」重要。

**3. 技术与索引**  
Sitemap 覆盖重要 URL；站点结构尽量扁平，核心页别藏太深。孤岛页、重复 URL、hreflang 错误按第三节逐项消。Lighthouse/PageSpeed 定期扫一遍。

**4. 权威与外链**  
调研笔记、可复现案例、行业小结，更容易被自然引用。客座、社群、演讲稿带回链接是常见白帽路径。页脚或文内放清作者信息与站点主体，信任信号更完整。

算法年年更新，2026 年依然绕不开 **E-E-A-T**、**体验指标**、**结构化数据** 和 **AI 参与后的 SERP 形态**。与其追每一次传闻，不如把**真实用户是否满意**当作北极星。

## 核心要点

- **SEO**：让用户与搜索引擎都舒服；2026 年拼的是内容质量、体验与信任，不是关键词密度。
- **E-E-A-T、SERP、零点击**：会改变「什么叫优化成功」——有时要看展示、引用和品牌，而不只是点击率。
- **DA/PA/TF 等**：第三方参考，适合竞品对比；**官方数据以 Search Console 为准**。
- **工具**：Search Console + PageSpeed + 富媒体测试作底座，hreflang/可读性/语法工具按需要加。
- **常见坑**：标题被改写、孤岛页、重复 URL 无 canonical、hreflang 指错、该进 Sitemap 的没进——按第三节清单排查即可。
- **系统做法**：关键词 + 内容深度 + 技术健康 + 自然外链，四块轮动，比单次「大招」更稳。

如果你只想做一件事：**先验证 Search Console 是否装对、数据是否稳定**，再挑一篇最重要的文章，按第二节工具把标题、速度、结构化数据过一遍——这一步已经足够甩开很多只收藏教程不动手的人。
